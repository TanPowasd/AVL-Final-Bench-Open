## 多大陆双层空间结构与规模

世界采用**大尺度地理栅格（L1）+ 战略分区与枢纽网络（L2）**的双层耦合空间模型：

- **L1 地理栅格层（`512 × 512` 地块，共 `262,144` 格）**：生成 `2..4` 块裂解大陆、远洋群岛链、内海海峡、山脉屏障与跨国大河流域。每格记录地形枚举、海拔、耕地肥力基准、风光禀赋、流域上下游有向图及所属 `region_id`。L1 在 `init` 采用紧凑调色板与游程编码一次性下发（仅在 `L06` 地形工程完工或重大环境演变时下发差分），专门用于判定跨区真实几何距离、输电距离损耗（`E02`）、临水建港条件（`L04`）、地峡运河与穿山隧道几何选址（`L06`）、上下游水文影响（`A01`）以及雷达与近地轨道覆盖遮挡（`G05`、`N06`、`C08`）。
- **L2 战略分区与网络层**：全图划分为约 **`340..420` 个陆地分区**、**`80..120` 个海域/洋区/海峡分区**（合计 `420..540` 个表层分区）、同构空域层及 **`24` 个近地轨道槽位**；分布有 **8 个主要国家**、**约 `36..48` 个中立城邦与自治领**、约 **`220..280` 座城市与战略枢纽（`Hub`）** 以及 **`1,100..1,500` 条分模态走廊边**（公路、铁路、河运、海运、空运、输电线、输水渠物理分网）。

## 长周期三级时间架构与固定精度账本

全局库存、资金、电量、研究点与行军进度使用整数毫单位（1标准单位=1000mU）；产线输入信用与在制品使用nmU（1mU=1000nmU）。规范整数任意精度，int64实现须检查溢出并报裁判故障，不能夹人口或截断资金。

- **仿真步（`Tick`）**：最小推进单位，单局总长 **`28,800 Tick`**（`t = 0 .. 28799`；v1.2 由 `9,600` 延长 3 倍，见 [0010](decisions/0010_longer_game_population_and_package_submission.md)）。
- **决策窗口（`Window`）**：**`1 Window = 5 Tick`**（共 **`5,760` 个窗口**，`w = 0 .. 5759`），`t % 5 == 0` 同步交互，窗口内由持续计划与本地条令自动执行。
- **工业与财政周期（`Cycle`）**：**`1 Cycle = 10 Tick = 2 Window`**（共 **`2,880` 个周期**，分奠基、扩张、转型、决胜四个 `720` 周期战略纪元；每 `20` 周期结算一次设施维护，整局共 `144` 次）。

## 同 Tick 八阶段无偏守恒流水线与共享资源仲裁（AR-013）

每个地点库存拆分为 **`available`（期初可用现货）**、**`locked_subsistence`（当步/当周期托管刚兑、现役部队口粮、水电农基础运行与居民基本口粮自动预留池）**、**`locked_order / locked_escrow / locked_build`（已冻结挂单/托管/施工专款专料）** 与 **`next_available`（当步新产出/新过户缓冲）**，每 tick 严格按 `P1 → P8` 推进，任何阶段均与座位号 `0..7` 及实体列表遍历顺序无关：

1. **P1 命令接入与基本生存/预算预留（每 tick 刷新生存预留；仅 `t % 5 == 0` 接入新命令）**：每 tick 开始时，系统首先按固定生存优先级（**托管刚兑 → 现役部队当步口粮 → 水电农基础运行 → 居民当步基本口粮与饮水**）从本地 `available` 自动划入 `locked_subsistence`，确保 P7 结算绝不会被 P3/P6 工业投料或市场卖单抢占；随后在 `t % 5 == 0` 逐条原子校验玩家命令与 `client_order_id` 幂等去重；挂卖单、签托管条款或启动施工时，**立即从本国剩余 `available` 或 `Treasury` 扣减对应数量转入 `locked_order` / `locked_escrow` / `locked_build` / `reserved_cash`**（已锁定库存绝不可在 P3 发电或 P6 投料中被再次动用）；远端离线单位按物理 `comm_delay` 入队延后生效。持续计划在每个 tick 开始时仅从剩余未锁定的 `available` 中按需预约当步份额。
2. **P2 环境更新、走廊等比配给与到货入库（每 tick）**：更新天气；走廊超限时按通行权限分档（在途车辆优先于新发车，见 [02 物流](02_economy_logistics_governance.md)）、同档按申请量等比配给（毫单位尾差由独立物流哈希决平）；跨节点 `travel_ticks >= 1`，当步抵达货物并入目的地 `available`，当步即可供 P3 发电与 P6 投料。
3. **P3 电网供需平衡与核冷安全（每 tick）**：电站扣 `1/10` 周期煤/油/氢/核料与冷却水（多电站争同一枢纽燃料/冷却水时按下方“共享池无偏等比分配规则”仲裁）；按连通子图扣除距离线损后分 6 优先级带（`B0–B5`）配电。
4. **P4 统一快照移动、截击与同时射击（每 tick）**：基于 P3 后统一快照推进移动与轨迹相交截击；按03§0关系状态机选择交战双方，同时结算火力、ACTION_LOSS耗材、基建附伤和撤退；封锁快照在下一tick P2/P3生效。**战损跨阶段一致性**：若某设施在 P4 被摧毁或易手，其在 P3 已消耗的燃料与已获配电量属物理已发生事实（不退回燃料，P7 照常结算当步已用电费），但该设施在当步 P6 的生产推进批量强制归零；被毁仓库挂出的未成交 P5 卖单在 P5 前自动撤销，其 `locked_order` 库存与 `available` 库存按相同战损比例损毁，剩余完好部分退回 `available`。
5. **P5 窗口末集合竞价出清（仅 `t % 5 == 4`）**：各 `(枢纽, 货物)` 执行统一出清价双边集合竞价；证券仅在 `t % 10 == 9` 的本阶段出清一次，成交货物从卖方 `locked_order` 原地转入买方 `next_available`（未成交且已到期挂单在 P7 末解锁退回 `available`）。
6. **P6 生产、采掘、科研与施工推进（每 tick 按 `1/10` 周期定额）**：仅从扣除 `locked_subsistence` 后的本地剩余 `available` 中扣减工业与科研投入，产出统一写入 `next_available`（次 tick 可用，杜绝单步全链级联）；每 `200 tick` 结算设施维护。
7. **P7 周期民生财政与缓冲提交（每 tick 末合并缓冲；`t % 10 == 9` 周期结算）**：优先动用 `locked_subsistence`（不足时再动用剩余 `available`）按固定优先级（托管刚兑 → 现役部队口粮 → 水电农基础运行 → 居民民生篮子 → 制造科研）结算消费、发薪征税、合资分红、支持度递推、人口迁移、合同托管与城邦评估；最后执行 `available += next_available; next_available = 0`。
8. **P8 迷雾与权限过滤观测生成（`init` 及 `(t + 1) % 5 == 0`）**：生成带来源、时间戳、置信区间及命令回执的窗口观测。

### 共享资源池无偏等比分配与两步提交规则（AR-013）

当同一枢纽/分区/矿脉内的多个消费实体 $i \in \{1, \dots, m\}$ 在同一阶段同优先级档位竞争同一有限公共池 $S \ge 0$（包括：同一枢纽 `available[g]` 原料/燃料/水/口粮、同一矿脉剩余可采储量 $R(t)$、同一枢纽剩余可用劳动池 $L_{\text{avail}}$、同一枢纽剩余可用公共仓容 $C_{\text{free}}$）时，严禁按数组遍历顺序先到先得，统一执行**两步无偏等比分配**：

1. **单池等比向下取整与确定性哈希尾差分配**：设各实体经产能、供电与人工上限裁剪后的独立需求为 $d_i > 0$（整数 mU），总需求 $D = \sum_{i=1}^m d_i$。
   - 若 $D \le S$，则每个实体实得 $a_i = d_i$；
   - 若 $D > S$，先计算整数保底份额 $a_i^{(0)} = \lfloor (S \cdot d_i) / D \rfloor$，剩余尾差 $r = S - \sum_{i=1}^m a_i^{(0)} \in [0, m-1]$ 按确定性哈希键 `H(world_seed, "pool_tie", tick, phase_id, pool_id, entity_id)` 升序依次给前 $r$ 个实体各加 `+1 mU`。该分配严格满足 $\sum_{i=1}^m a_i \equiv S$、$0 \le a_i \le d_i$，且将实体列表任意重排后结果逐位相同。
2. **多投入产线与出库仓容的两步提交**：对需要多种投入的产线 $f$，第一步对每种投入 $g$ 及劳动池独立计算其可获配额 $a_{f,g}$ 并求可行批量上界 $\Delta x_f^{(1)} = \min_{g} \lfloor a_{f,g} / a_{r,g} \rfloor$；第二步若同枢纽总产出超过剩余仓容 $C_{\text{free}}$，将各产线批量按 $C_{\text{free}}$ 等比缩减至 $\Delta x_f$，仅按最终实跑批量 $\Delta x_f$ 扣减各投入与仓容，未用完的预分配额度当场留在 `available` 中。

## 数值值域、纳单位残差账本与确定性随机流规范（AR-014 / AR-040）

1. **纳单位（`nmU`）预扣投料信用与整机整数释放账本（防拆小批量白嫖投入与防半台整机释放）**：
   - 每条产线 $l$ 维护当前配方的投料信用余额 `line_input_credit[l, g]`（单位：`nmU`，`1 mU = 1,000 nmU`）与产出累加器 `line_output_accum[l, g]`（单位：`nmU`）。
   - 当产线在当步推进批量 $\Delta x \in \mathbb{Z}_{>0}$（单位：`mU` 周期批量，即 $10^{-3}$ 周期）时，对每种配方投入 $g$（单周期定额 $a_{r,g}$），当步精确消耗为 $\text{req}_{\text{nmU}} = \text{round}(a_{r,g} \times 1000) \times \Delta x$（`nmU`）。
   - **双分支精确核减投料信用**：
     - 若 `line_input_credit[l, g] >= req_nmU`：无需从仓库新扣现货（`deduct_mU = 0`），**直接核减线上信用** `line_input_credit[l, g] -= req_nmU`；
     - 若 `line_input_credit[l, g] < req_nmU`：产线必须**先从枢纽 `available[g]` 向上取整预扣整数毫单位**：
       $$\text{deduct}_{\text{mU}} = \left\lceil \frac{\text{req}_{\text{nmU}} - \text{line\_input\_credit}[l, g]}{1000} \right\rceil$$
       若 `available[g] < deduct_mU`，则该批量不可行（按 `available[g]` 反推最大可行 $\Delta x$）；预扣成功后执行 `available[g] -= deduct_mU`、`line_input_credit[l, g] = line_input_credit[l, g] + 1000 * deduct_mU - req_nmU`。
   - **可分货物与不可分整机的分级释放规则（AR-040）**：产出端首先累加 `line_output_accum[l, g] += round(b_{r,g} * 1000) * Δx`（`nmU`）：
     - 对**普通可分库存物品**：当 `line_output_accum[l, g] >= 1,000 nmU`（`1 mU`）时，向 `next_available[g]` 释放整数毫单位 $\text{release}_{\text{mU}} = \lfloor \text{line\_output\_accum}[l, g] / 1000 \rfloor$，并保留余数 `line_output_accum[l, g] %= 1000`；
     - 对 `data/industry.json` 标为 `indivisible=true` 的整机：`whole=acc//1000000; release_mU=whole*1000; acc%=1000000`。例如1250000nmU仅释放1000mU，余250000nmU；不得按不存在的别名判整机。
   - **换线/拆线清零**：产线切换配方或被拆解/摧毁时，该线残留的 `line_input_credit` 与未满释放阈值的 `line_output_accum` 直接报废归零，绝不跨配方挪用。
   - **验证（P076 反例）**：`P076`（`precision_pack = 0.1`）连续推进 10 次 `1 mU`（`0.001` 周期，每次 $\text{req}_{\text{nmU}} = 100\text{ nmU}$）：第 1 次从仓库预扣 $\lceil 100 / 1000 \rceil = \mathbf{1\text{ mU}}$ `precision_pack`，`line_input_credit` 变为 `1000 - 100 = 900 nmU`；第 2..10 次走 `>= req_nmU` 分支依次核减 `100 nmU` 直至 `0 nmU`；第 11 次再次触发预扣 `1 mU`，100% 守恒。
2. **全局除零保护、概率夹取与 `int64` 溢出边界**：
   - **概率统一夹取**：所有随机事件概率（含维护故障率 $\text{clip}(0.08 D_{\text{maint}}, 0, 1)$、机组强迫停运率、网络攻击/反卫星/入轨成功率、AI 失控概率）在抽样前一律执行 $p \leftarrow \text{clip}(p,\, 0.0,\, 1.0)$。
   - **汇率硬值域夹取**：本币兑 RU 汇率硬限制在 $e_p(c) \in [0.05,\, 20.0]$（即 `50 mU .. 20,000 mU`），单步更新后执行 $\ln e_p \leftarrow \text{clip}(\ln e_p,\, \ln 0.05,\, \ln 20.0)$，限制汇率变化范围；不构成其他账户的int64安全证明。
   - **零分母保护默认值**：住房容量 $H_{\text{cap}} = 0$ 时，若 $P > 0$ 则 $H = 0$，若 $P = 0$ 则 $H = 1$；贸易比 $TB_p / \max(\text{GDP}_p, 100\text{ RU})$；全球 GDP 加权均值 ($i_w, \pi_w$) 的各国权重取 $\max(\text{GDP}_p, 100\text{ RU})$；开局或全员未解锁 `F02` 时全球基准利率锚定 $i_w(0) = 5.0\%/\text{年}$；矿脉寿命 $L_k = \text{Reserve}_k / \max(\overline{\text{Extract}}_k^{(20)}, 0.1)$；电网无发电且有负荷时边际电价取切负荷上限 `50.0`，无发电且无负荷时取上一周期均价（初值 `2.0`）。
3. **确定性哈希 PRNG 与超越函数冻结规范**：
   - 任何随机抽样点由唯一元组键 `key = JSON([world_seed,stream_tag,tick,location_id,sub_idx], compact=true)` 经 UTF-8 编码后计算 `SHA-256(key)`，取前 8 字节大端无符号整数 $u_{64} \in [0, 2^{64}-1]$，映射为 IEEE-754 双精度均匀随机数 $u = (u_{64} \gg 11) \times 2^{-53} \in [0, 1)$。
   - 标准正态分布 $\varepsilon \sim N(0, 1)$ 统一由同流 `sub_idx = 0, 1` 生成的 $(u_1, u_2)$ 按确定性 Box-Muller 公式 $\varepsilon = \sqrt{-2\ln(\max(u_1, 2^{-53}))}\cos(2\pi u_2)$ 计算。
   - 算术与超越函数（`exp / log / sqrt / sin / cos / tanh`）在 Python 3.11+（`glibc libm` IEEE-754 binary64 最近偶数舍入）环境下运行，并在每个阶段提交到账本前通过 `int(round(x_mU))` 落地为整数毫单位（数值范围见11），仅保证已冻结运行时指纹内重放；实现验收必须记录解释器、libm、架构和容器镜像摘要，不承诺不同Python3.11+版本逐位相同。
