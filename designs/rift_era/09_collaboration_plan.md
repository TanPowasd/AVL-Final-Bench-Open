# 多 AI 完善任务建议

这是一份可直接分配的任务清单，不代表已经启动任何其他 AI。默认先完善设计，再决定原型与实现范围。

## 公共输入

每个参与者先阅读 README、AGENTS、00、01、08 和 decisions/0001_scope.md。科技或物资引用使用稳定 ID，不按名字重新创建同义对象。

## 分工

| 任务 | 负责范围 | 必须与其他任务对齐 |
|---|---|---|
| A：世界与时序 | 实体、控制权、世界生成、同 tick 结算 | B 的库存与运输，C 的作战，E 的采样条件 |
| B：产业与科技 | 科技前置、生产闭环、替代路线、人口与建设投入 | A 的地点与权利，C 的装备消耗，E 的计分防套利 |
| C：军事与情报 | 编队、装备配置、补给、战斗、侦察与通信 | B 的实体物资，A 的冲突结算，D 的占领与外交 |
| D：治理与外交 | 人口、地方响应、合同、城邦和技术扩散 | A 的控制权，B 的财政与物流，E 的影响力计分 |
| E：评测与对抗审查 | 国力、连续评分、seed/座位、基线与漏洞 | 所有系统的真实收益与可操作的评分信号 |
| F：接口与计算预算 | 策略协议、隔离、同步、资源预算与性能方案 | A 的时间，所有系统的观测与命令粒度 |

人数较少时可以合并任务；共享工作区时先划分文件责任。不同任务不要各自定义一套互不兼容的时间、货币、物资和伤害单位。

## 每个任务的交付格式

1. 你保留了哪些既定目标，修改了哪些候选规则。
2. 可以直接按其执行的规则、公式或数据，而不只是主题描述。
3. 至少一条跨系统决策链，说明新增规则如何改变玩家选择。
4. 输入、输出和依赖哪些其他任务提供的定义。
5. 边界情况、可能被利用的漏洞，以及仍未解决的问题。
6. 修改文件清单和设计检查结果；未做的验证明确列出。

## 交接与合并

并行建议先放在 `proposals/` 中，每份提案使用独立文件名，如 `B-industrial-maintenance.md`。直接负责某组文件的 AI 可以修改该组文件，但应在 CHANGELOG 中记录范围。

需要变更共同约定时创建带编号的决策记录，列出旧语义、新语义、受影响文件和迁移方式。科技/物品 ID 不随意重排；确需删除或替换时列出映射。

整合者检查跨文档一致性、运行目录结构检查，并追踪仍待决定的事项。任务授权若已包含定稿或实现，应继续执行相应工作；此流程不要求额外重复向用户请求许可。
