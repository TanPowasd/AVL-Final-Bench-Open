# 0010 单局延长 3 倍、人口改逻辑斯蒂、实验室产出上调、压缩包提交

- 日期：2026-11-03
- 状态：已采纳为候选规则；数值仅经过理想化上限估算（`prototype/bound.py`），尚未经过强参考策略实测。

## 背景

战略层原型 v0（`prototype/`）测得：按 v1.1 常数，研究被劳动卡死。理想化上限在 960 周期内约 9 万研究点，而全树约 54.6 万；一个 6 阶终端连同前置需要 3.0–9.2 万。新增的 5–6 阶在实际对局中基本是死内容。

用户 2026-11-03 选择“提高人口增长上限与高阶实验室产出”，随后要求单局时长再乘 3，并要求本题提交改为压缩包。

## 决定

1. **局长 ×3**：`28,800 Tick` = `5,760` 个决策窗口 = `2,880` 个工业周期。四个战略纪元各 `720` 周期；设施维护结算 `144` 次。
2. **思考预算同比放大**：每窗口基础时限仍为 `0.5 s`；`time_pool` 由 `150 s` 改为 `450 s`；单局累计上限由 `1,200 s` 改为 `3,600 s`。
3. **人口改逻辑斯蒂增长**：$\Delta P = r P (1 - P/K)$，$r = 0.20\%$/周期，$K = 3 \times$ 开局人口（主要国家 `600`）；口粮满足率 `< 0.80` 时 $r = 0$。原规则是 `0.15%` 无上限指数增长，延长到 2,880 周期会长到约 1.5 万人口，必须加承载上限。
   - **已被取代（2026-11-03，v1.3）**：本条逻辑斯蒂承载上限 K 由 [0012](0012_v13_population_finance_forex_ai.md) 第 1 条取代——人口不设上限，改为出生/死亡率模型，上限由口粮、住房、发展指数与医疗内生决定。本条保留为历史记录。
4. **高阶实验室产出 ×1.5**：`P077` 8→12，`P079` 12→18，`P102` 30→45 研究点/周期。
5. **提交形式**：一个 `.zip` 压缩包，可多文件、多目录，不限制单个文件大小；根目录必须有 `main.py` 入口；仍只允许 Python 标准库。评测机拒绝绝对路径、`..`、符号链接与设备文件，解包后只读挂载。

6. **矿藏储量 ×3**（2026-11-03 08:20 用户采纳推荐）：各有限矿脉储量随局长同比放大 3 倍，高强度开采进入尾矿区的时间由约 350–550 周期推迟到约 1,050–1,650 周期。原型中储量 ×1 的长局必然在约 1,000–1,500 周期断煤崩溃。

## 理想化上限（`prototype/bound.py`）

| 方案 | 整局研究点上限 | 占全树 |
|---|---|---|
| v1.1：960 周期，指数 0.15% | 约 9.0 万 | 16% |
| **v1.2：2,880 周期，r=0.20%，K=600，实验室 ×1.5** | **约 92 万** | **169%** |
| 对照 K=400 | 约 65 万 | 119% |
| 对照 K=800 | 约 117 万 | 214% |

该上限假设 35% 的人口无摩擦投入科研链，并且实验室按最优顺序升级，所以是宽松上界。原型中的启发式 bot 只达到上限的 1–2%。v1.2 的意图是：完美策略理论上能覆盖全树，但实际策略只能覆盖一部分，必须在 11 条主干与互斥制度之间取舍。若实测发现强策略接近覆盖全树，再按 K=400 收紧。
