# 接手 AI 的协作说明

用户的新指令始终优先。本文件不增加用户确认或批准流程。

1. 当前交付物是独立设计包。可以在授权的设计任务范围内完善文档和数据；不要把设计草案表述为已实现的题目或已通过的平衡测试。
2. 先读 README、设计理念和未决问题。无需访问原对话，也不要把缺失的聊天内容自行编造成已确认要求。
3. 当前默认工作范围是本目录。若用户另行授权引擎实现或题库集成，以新授权为准；否则不要改动已有题目、评分器、公开导出包或提交文件。
4. 已确定的用户要求与规则参数分开。`rift_era_rules_r6` 已冻结，不再就地修改规则或参数；确需变更时发布新规则版本，并记录动机、依赖、代价和未决问题。不改变数据与既定行为的文字勘误可直接修正，须记入CHANGELOG。
5. 科技和工业目录以 data 下 JSON 为事实源。保持 ID 稳定；修改后运行 `python3 tools/catalog.py render` 和 `python3 tools/catalog.py check`。不要只修改生成的 Markdown 表。
6. 科技“解锁”、工厂“能生产”、物资“已送达”和部队“能使用”是四件事。补充规则时保持它们之间的联系，避免免费获得产能或跨地图瞬移库存。
7. 同时交付修改的其他 AI 使用独立提案文件；不要覆盖别人的提案。需要修改共同文件时，说明本次负责的文件和接口，保留已有有效改动。
8. 不把某个机制称为必定新颖、必定更难或必定公平。把这些写成目标，并说明将来能用什么证据评价。
9. 尚未定义的伤害、市场、人口、评分等公式必须明确标为未定。不得用隐藏补丁或任意常数掩盖缺口。
10. 当前任务不要求自动启动其他 AI、联系外部人员、上传到第三方或消耗付费服务。协作分工供用户分配任务时使用。
