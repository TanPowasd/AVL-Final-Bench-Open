## 1. 策略要点

底座是 `agents/baselines/merchant.py` 里内嵌的公开 `ref` 配置（`merchant.py` 去掉 `CFG.update` 即得；以下称“ref 代理”）：
学习率探针 + N×D 探针网格拟合缩放律、按拟合选 N/D、统一价拍卖买卡、扩容/建机房、招人、按序研究、季度融资、logit 最优定价。
在此之上的改动（全部只用观测里的公开信息，每项都可在 `CFG` 里关掉）：

1. **零成本逐 tick 存档**：README 写明 `run_ctl ckpt` “立即写存档，不扣吞吐”。主任务每 tick 手动存档、自动存档间隔调到极大，
   硬件故障/尖峰/抢占最多丢 1 tick；选卡与规划用新的有效吞吐估计 `(1-f)^3/(1+2.5f)`；学习率乘子 0.92→0.98（尖峰可零成本回滚）。
2. **长任务 + 中途发布**：代际改为 `[2600, 7500, 26278]`。第 3 代从约 7000 tick（`algo_eff_3` 已完成，`N_eff`×1.5 生效）一直训到局末，
   在 13000/19500/24000 tick 发布中途存档供 API 市场使用（若不如在架旗舰则立即下架，C 仍计入），末代在 t=26254 发布。
   ref 每代从零重训，后两代 C 几乎不涨；长任务把全部算力累积到一个模型上。参数量封顶 120B（防止服务成本失控）。
3. **蒸馏 9.5%**：主训练配比放 9.5% 蒸馏数据（买 NPC/OPEN-1 旗舰输出，单价 ≈ 价格/1000 M/B，几乎免费），低于 10% 封顶线、远低于 20% 诉讼线；
   对小数据域（math/dialog/science）是显著的有效 token 增量。
4. **研究完成后裁员**：计划内科技约在 6000–7000 tick 全部完成，此后研究点无用，裁掉全部研究员把工资省下来买卡。
5. **终局市场（对抗赛的决定项）**：终局估值里 `96 × 最后 730 tick 服务毛利` 远大于其他各项，而 API 份额每周最多迁移 ±0.15。
   - t≥24500：低价（找出使估计目标份额 ≥0.9 的最高价，通常 0.5）抢份额，云租按需卡补足服务算力保证不丢单；
   - t≥25544（最后 730 tick 前）：旗舰定价 100（上限），份额每周按上限衰减，最后一个月营收比正常定价高一个数量级。
6. **局末融资**：第 11 季度不做常规融资，t=26266 按 `V_pre = 240×近 730 tick 营收 + …` 融满（金额截断为 V_pre，股权减半、现金 +V_pre）。
   因为融资估值用 240 倍月营收而终局估值只算 96 倍月毛利，这一步在收割之后总是增值。

7. **修复 ref 的探针卡死**：学习率探针若在第一次存档前发散，ref 的 `rollback` 失败，整局停在探针阶段、一个模型都不发布（C=0）。
   本对手把这类探针记为失败并用其余探针拟合；主任务首存档前发散也会重开。

> 第 5、6 项是规则允许的“计分设计套利”（README 2.6/2.7/第 4 节明文规定的迁移上限、终局 96× 毛利、融资估值公式），不依赖引擎 bug，
> 也不读任何隐藏信息。但它们让对抗赛分差主要由最后 6 周的定价博弈决定，建议出题方评估是否属于预期玩法（见第 5 节）。

## 2. 测法

- 引擎直接调用 `engine.play()`（与 `scripts/spar.py` 相同的对局与计分公式；`spar.py` 的路径守卫不允许加载 `calibration/` 下的文件，
  所以用 `dev/ai_training/batch.py`：可续跑、每局一行 JSONL）。子进程模式，与正式评测一样受 2 s/tick、120 s 时间池、2400 s 总预算约束。
- 每局分数：单人赛 `100 × C`；对抗赛 `50 + 50·tanh((V_我 − V_对手)/4846.39)`（`scoring_v2`）。
- 95% CI：按种子块 bootstrap（4000 次重采样），与 README 的正式口径一致。
- 种子：评测用 **1001–1064**（调参只用过 1–8，评测种子与调参种子不重叠）。盐值 `practice`。
- **座位**：merchant（种子 1001–1016）与 scaling（1001–1008）双座位都跑了，25 对交换座位结果**逐位相同**（引擎对两席完全对称，
  bot 确定性，`PYTHONHASHSEED=0`）。机器只有 2 核且同时跑另外两个任务，单局 7–70 s，因此其余对局只跑 0 号座位
  （与双座位平均等价）。“局数”一列是实际跑的局数，均分/CI 先按种子平均再统计。
- 种子数：单人赛、ref 代理、merchant、scaling 64（2026-11-07 补满）；blank、starter、三项反制测试各 16（均 ≥16，未到 64 的原因是机器太慢，见第 6 节）。
- 对手 `ref 代理` = `merchant.py` 去掉 `CFG.update` 的公开 ref 配置（`dev/ai_training/ref.py`），只是私有参考对手的猜测性代理，
  不代表正式参考对手。

## 4. 反制测试（可剥削性）

| 测试 | 对手构造 | 结果 | 结论 |
|---|---|---|---|
| 抢拍卖 | ref + 出价 2.6×基准×热度、每周花 70% 可支配现金、融资上限 1500 | 16/0，均分 97.5 | 对手卡更多、C 略高（0.894 vs 0.888），但它不打终局市场，价值差仍饱和 |
| 挖角 | ref + 每周 5 次以 0.0015 M/tick（约市价 5–10 倍）挖我方研究员 | 16/0，均分 97.1 | 我方研究约在 7000 tick 前完成、之后裁员，挖角收益有限；对手自己被高薪拖到破产（价值 0） |
| 同款终局收割 | ref 训练 + 本对手的终局抢份额/收割/局末融资（`opp_refgouge.py`） | **11/5，均分 66.8，CI [42.9, 86.4]** | **主要弱点**：双方都收割时，胜负取决于最后 6 周谁的份额高，tanh 尺度下非 0 即 100 |

种子 1008 的逐周轨迹（对同款收割，hark 输 12,345 vs 99,893）显示的失败机理：
1. 长任务的中途存档参数量大（N=120B），ref 式的服务卡上限（训练优先、服务最多占 45% 算力）在常规阶段供不上需求，
   丢单率 0.3–0.5，声誉一路掉到 −2.2（效用 −2.2，等于把价格抬高 4 倍）；
2. 抢份额阶段租卡服务 120B 模型很贵，现金跌破 80 M 后按保护逻辑停租，份额在收割窗口开始前被对手反超（0.20 vs 0.72）。

## 5. 已知弱点与给出题方的说明

1. **终局对称收割时不稳**（见上）。可改进：常规阶段按服务容量定价（让目标份额 ≤ 容量）以免丢单掉声誉；
   终局服务用单独训练的小参数模型；第 10 季度预先融资给抢份额阶段留足现金。均未实现。
2. **弱世界的稀释**：沿用 ref 的“每季度在可支配现金 <150 M 时融 15% 估值”，在早期模型弱、营收低的种子（如 1010、1006）
   会在低估值下反复融资，股权被稀释到 0.12–0.19，对 blank/starter 的最低单局分只有 53–64（仍然赢）。
3. **单人赛最差种子**：1010 只有 C=0.818（早期模型弱 → 营收低 → 买卡少）。
4. **计分设计**：对抗赛价值几乎全部来自“最后 730 tick 毛利 ×96”和“局末按 240× 月营收融资”。只要一方在最后一个月把价格定到上限，
   价值就到 3–15 万 M，tanh(Δ/4846) 立刻饱和；对不做这件事的对手胜率 100%，做了的双方之间则是高方差的抛硬币。
   如果这不是预期玩法，可考虑：份额迁移上限对涨价方不对称、终局毛利取全年平均、融资估值与终局估值使用同一倍数、或限制局末融资。
5. ref 代理只是对私有参考对手的猜测；若私有参考对手同样做终局收割，对抗赛分数会接近第 4 节的 66.8 而不是 96.5。
