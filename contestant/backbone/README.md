# 骨干争夺（Backbone Wars）

双人中立骨干网运营商经营对抗赛。一局模拟 `8` 周（`8064` tick，`1` tick = `10` 分钟，`1` 天 = `144` tick），两家运营商（A、B）与传统运营商（NPC）在包含 `100..140` 座城市、`260..380` 条共享链路的对称骨干网上竞争机房（PoP）选址、链路长短租、显式多路径流量工程、边缘内容缓存、企业专线招标与互联互通，终局按净资产 `NW` 评定成绩。

---

## 1. 交付与运行限制

- **最终统一提交路径（必交）**：`../submissions/backbone.py`（即工作区顶层 `submissions/backbone.py`；本地测试通过后必须将最终文件以题目名保存至此目录，正式评分仅从顶层 `submissions/` 自动分发）。
- **题内开发自测路径（可选）**：`agents/submissions/my_agent.py`（`scripts/spar.py` 同时支持直接读取 `../submissions/backbone.py` 或 `agents/submissions/my_agent.py`）。
- **语言与依赖**：单个 UTF-8 Python 3.10+ 源文件，仅允许使用 Python 标准库，禁止联网、禁止读写外部文件或读取对手代码。
- **运行方式**：裁判为每局的双方各启动一个独立子进程，通过 `stdin / stdout` 按行交互 UTF-8 JSON。子进程的工作目录是提交文件所在目录，`stderr` 被丢弃，环境变量 `PYTHONHASHSEED=0`。
- **交互时限**：初始化握手限时 `10.0` 秒；每 tick 墙钟时限 `0.2` 秒；单局累计总思考预算 `20` 分钟（`1200` 秒）。
- **时间池**：另有独立于单 tick 的时间池 `60` 秒（整局一份、不回补）。某 tick 用时超出单 tick 时限的部分从池里扣，池有余量就不算超时；池用完后恢复单 tick 硬时限。剩余池量见观测字段 `time_pool`（秒），也计入累计总预算。
- **超时与容错**：单 tick 超时或输出非 JSON 对象时，该 tick 按空动作 `{}` 处理，迟到回复按未答消息计数自动丢弃对齐（观测 `missed` 报告累计丢失次数）；未回复的消息积压达到 `50` 条、进程崩溃或总预算耗尽后，剩余 tick 全部按空动作处理。你在第 `t` tick 观测后返回的动作，在第 `t + 1` tick 的收动作阶段生效。
- **动作异常**：动作按第 2.2 节的字段顺序逐项执行。字段类型错误（如 `{"peer_accept": [[1]]}`、路径里嵌套列表）引发异常时，本 tick 该项之后的动作全部作废，`res` 里出现 `exception: ...`，对局继续。
- **非法数值**：动作里任何数值是 `NaN`、`Infinity` 或绝对值超过 `1e15` 时，本 tick 的整个动作作废，`res` 里出现 `non-finite or oversized number`，对局继续。
- **工作区边界**：读写范围和规则优先级见工作区顶层 `README.md`。权威引擎实现位于 `engine/engine.py` 与 `engine/mapgen.py`。

## 2. 完整规则

### 2.1 对称地图与链路结构
- **镜像对称生成**：每个随机种子先生成含 `3` 个大区（编号 `0..2`，时区偏移 `-2 / 0 / +2` 小时）、`50..70` 座城市的半张图，再沿 `x` 轴镜像生成另外 `3` 个大区（编号 `3 / 4 / 5` 的时区偏移依次为 `+12 / +10 / +8` 小时），两半之间由成对镜像的海缆连接；全图城市数为偶数 `100..140`，无向链路 `260..380` 条。所有随机事件、需求噪声、现货背景负载与类目热度均按镜像成对同步发生。
- **城市属性**：坐标 `(x, y)`（km）、所属大区 `region`、归一化人口权重 `pop`（帕累托 `1.25` 分布截断 25 倍后全图和为 `1`）、建站地价 `land = min(2.5, 0.5 + 60 * pop + U(0, 0.3))`、电价系数 `elec ~ U(0.7, 1.4)`。
- **三类无向链路**：
  - `land`（陆缆）：容量 `40..400`，传播延迟 `lat = 1 + 距离 / 200` ms，每单位每 tick 基础租价 `base = 0.0006 + 0.00008 * lat`。
  - `mw`（微波，仅出现在 `<= 450 km` 补边）：容量 `10..40`，`lat = 0.5 + 距离 / 290` ms，`base = 0.0024 + 0.00008 * lat`；大区下雨期间容量（含已租容量实际承载力）减半。
  - `sub`（跨海海缆）：容量 `400..1600`，`lat ~ U(40, 120)` ms，`base = 0.0008 + 0.000015 * lat`。
- **链路容量切分**：每条链路总容量 `cap` 固定分为三部分：**可租池 `70%`**、**免费现货共享池 `20%`**、**NPC 自用 `10%`**。

### 2.2 每 tick 结算顺序

1. 处理到期事件并生成公告。
2. 按座位 A、B 依次执行动作。单方动作固定按 `sell`、`build`、`expand`、`lease`（只登记）、`release`、`routes`、`defer`、`price`、`cache`、`bid`、`peer_offer`、`peer_accept`、`ups`、`scrub` 的顺序处理。
3. 结算本 tick 全部租约请求。
4. 处理到期租约、PoP 建成、端口扩容、过期互联报价和到期互联协议。
5. 结算网络流量和业务收入。
6. 扣除运营费，结算互联费和合同款，判定破产。
7. 每日末（`t % 144 == 143`）迁移市场份额并更新类目热度。
8. 生成观测。

### 2.3 起始状态、机房（PoP）与破产
- **初始状态**：现金 `20,000`；双方各自在半图总人口最大大区的人口前二城市（及对应镜像城市）拥有 `2` 座已建成起始 PoP（初始占该城三类业务各 `0.35` 份额，造价按 `land * 3000` 计入初始折旧账面）；初始无链路租约。
- **破产红线**：信用下限为 `-10,000`。一旦 `cash < -10,000` 即判定破产（`bankrupt = true`），此后一切主动动作作废，既有运营费照扣，所有城市份额每日流失 `8` 个百分点。`build`、`expand`、`cache`、`ups` 和租约扣款后现金不得低于信用下限，否则该动作失败。
- **机房（PoP）规则**：每方每城至多 `1` 座 PoP，**全图每方最多同时拥有（含在建）`20` 座 PoP**。
  - `build {"city": c}`：花费 `land * 3000`，`36` tick 后建成；建成时从 NPC 获得该城三类业务各 `0.05` 初始份额；建成后每 tick 固定运营费 `(land * 40 * elec) / 144`。
  - **端口容量**：初始 `200` 单位骨干端点流量（本地缓存直接命中的视频流量不占端口、不进骨干；超载部分按比例丢包）。扩容 `expand {"pop": c, "units": u}` 要求 `u >= 1`，按 `100` 单位向上取整，每 `+100` 单位花费 `800`，`24` tick 后生效。在建 PoP 也可以扩容。
  - **备用电源 `ups [c, ...]`**：每座一次性花费 `2,000`，免疫城市断电事件。
  - **DDoS 清洗 `scrub [c, ...]`**：持续设定当前开启清洗的 PoP 集合，每座每 tick 费用 `50`，开启期间免疫 DDoS 端口放大。
  - **出售机房 `sell [c, ...]`**：回收该 PoP 及其扩容/缓存/UPS 当前账面价值的 `60%`，该城本方市场份额立即归零。在建 PoP 也可以出售。

### 2.4 流量需求、价格、SLA 与每日份额迁移
- **无向城市对需求**：对任意无序城市对 `(i, j)`（`i < j`），基准总流量 `D_ij = 50000 * pop_i * pop_j / max(距离_km / 1000, 0.3)^1.2`。仅当本方在 `i` 与 `j` 均拥有已建成且未断电的 PoP（或通过互联协议接入 `j`）时可服务 `(i, j)`。
- **三类业务参数**：

| 类别 `cls` | 需求占比 | 延迟上限 | 单价基准 | 特殊机制 |
|:---:|---:|---:|---:|---|
| `video` | 60% | 150 ms | 1.0 | 支持 PoP 本地内容缓存（共 20 个类目 `0..19`） |
| `rt` | 15% | 40 ms | 4.0 | 路径抖动 `> 10 ms` 时 SLA 系数额外 `×0.8` |
| `backup` | 25% | 无上限 | 0.4 | 支持 `defer` 延后队列（最多延后 `36` tick，超期作废） |

- 当两端均为本方自有 PoP 时，本方在 `(i, j)` 类别 `k` 的当 tick 需求为：
  `D_ij * 占比_k * ((s_{i,k} + s_{j,k}) / 2) * ((F_ri + F_rj) / 2)`，其中大区时变因子 `F_r = (1 + 0.55 * cos(2*pi*(本地小时 - 21)/24)) * 周曲线[星期] * (1 + 0.004 * 天数) * (1 + AR1噪声)`，周曲线为 `[1, 1, 1, 1, 1.05, 1.15, 1.10]`。
- **收入与 SLA 系数**：
  - 有效送达流量每单位收入 = `单价基准 * 两端大区价格倍数均值 / 35 * SLA系数`。
  - 单条路径延迟 `<= 延迟上限` 时路径延迟系数为 `1.0`，在 `(上限, 2 * 上限)` 内线性降至 `0`，`>= 2 * 上限` 为 `0`（`backup` 恒为 `1.0`）；再乘路径存活率 `(1 - 丢包率)`；`rt` 类若 `各分流路径延迟加权标准差 + 0.5 * 现货附加延迟之和 > 10 ms`，再乘 `0.8`。
- **大区定价 `price`**：按 `(region, cls)` 设定价格倍数 `value`（初始 `1.0`，范围 `[0.2, 5.0]`，超出时截断），单次调整超出 `±30%` 自动截断，每个 `(region, cls)` 每天（`144` tick）最多修改 `2` 次。截断后与原值相同的调整不占次数。
- **每日市场份额迁移（每 `144` tick 一次）**：
  - 玩家在某城某类的 logit 效用：`U = -2.0 * 价格倍数 + 2.0 * SLA3 - 0.3 * 断线次数3 + 1.0 * 当前份额`（价格倍数取该城所在大区；`SLA3` 为近 3 天有效送达/需求，没有数据时按 `0.9`；某 tick 该城总送达 `< 0.5 * 总需求` 由通转断计 1 次断线）。NPC 固定 `价格倍数 = 1.0, SLA3 = 0.85` 并带同样惯性项。每方每日份额变动截断在 `[-0.08, +0.08]`，余量归 NPC。

### 2.5 链路租赁、现货池与路由规则
- **租约 `lease {"link", "units", "term", "max_price"}`**：
  - 链路当前未打折单价 `lp = base * 涨价事件系数 * (1 + 3 * u^2)`，其中涨价事件系数取链路两端大区的较大值，`u` 为全体已租量占可租池（`0.7 * cap`）的比例。
  - 若 `lp <= max_price` 且扣除预付款后 `cash >= -10,000`，按期限 `term in {1, 7, 28}`（天，即 `144 / 1008 / 4032` tick）享受折扣系数 `1.0 / 0.8 / 0.6`，立即全额预付 `lp * 折扣 * units * 期限tick` 并当 tick 生效（同 tick 争抢剩余可租容量时按 `max_price` 高者优先，同价平分；容量不足时可部分成交，实际成交量见 `res` 回执）。
  - `release {"lease_id": id}` 提前退租，退还剩余未摊销预付款的 `50%`。也可以直接写租约 id，如 `"release": [88]`。
- **路由 `routes` 与拥塞物理模型**：
  - 未显式指定路由的 `(a, b, cls)` 自动走**默认路由**（仅在当前未断开链路上按传播延迟 `lat` 求最短路，链路断/修时自动重算）。
  - 显式下发 `routes {"src", "dst", "cls": "video"|"rt"|"backup"|"all", "paths": [[城市序列], ...], "split": [...]}`：最多 `4` 条路径，每条路径的首尾必须是 `src`、`dst`，相邻城市之间必须有链路；`split` 长度须与 `paths` 相同，省略时等分，自动归一化；不合规时整条路由作废并写入 `res`。`paths: []` 删除显式路由恢复默认；路由按无向城市对生效，`(a, b)` 与 `(b, a)` 是同一条；**显式路由在链路断开时不会自动绕行**，经过断开链路的流量全部丢失。
  - 本方在某链路上的骨干总流量先走本方在该链路的租约容量（排队延迟 `0.5 * u_own / (1 - min(u_own, 0.95))` ms），超出本方租量的部分自动溢出至该链路的**现货共享池**。
  - 现货共享池总负载率 `rho = (NPC背景负载 + A溢出 + B溢出) / 现货池容量`：现货部分的路径延迟为 `lat / (1 - min(rho, 0.95))`，当 `rho > 1` 时现货流量按 `(rho - 1) / rho` 比例丢包。单条链路的延迟和丢包按租约部分与现货部分的流量占比加权，路径延迟是各链路之和，路径存活率是各链路 `(1 - 丢包率)` 之积。NPC 背景负载 = `现货池容量 * bg * F_r`，其中 `bg ~ U(0.2, 0.6)`（每条链路一个，镜像链路相同），`F_r` 取链路所属大区的时变因子。

### 2.6 内容缓存、备份延后、企业合同与双边互联
- **边缘视频缓存 `cache {"pop": c, "alloc": {"类目0..19": 单位}}`**：每座 PoP 每天最多改 `1` 次，新 `alloc` 整体替换旧分配，在建 PoP 也可以配置；若 `sum(alloc)` 超过该 PoP 已购缓存总容量，差额向上取整后按 `500 / 单位` 立即扣款扩建（容量只增不减），已装缓存每天每单位运营费 `5`。类目 `k` 分配 `a` 单位的本地命中率为 `a / (a + 3)`；城市对 `(i, j)` 视频总缓存命中率取两端 PoP 命中率均值，命中部分直接送达计费，不占端口与骨干链路。
- **类目热度**：同一大区内 20 个类目按 Zipf 分布（第 `i` 热的权重正比于 `1 / i`），镜像大区的排名相同。每天漂移一次：随机交换 `3` 对相邻排名，并有 `20%` 概率把一个非前三的类目提到前三。`day.heat` 是 `{城市: [20 个类目的视频量]}`，只含本方 PoP 看到的流量，带 `±10%` 高斯噪声。
- **备份流量延后 `defer {"src", "dst", "units"}`**：只对当 tick 生效，不会延续，城市对不分方向。`units > 0` 将本 tick 该对备份流量入队延后（最多延后当 tick 该对的备份需求）；`units < 0` 从队列 FIFO 取出补发；入队超过 `36` tick 未发出的部分自动作废（计入 SLA 分母且无收入）。
- **大客户专线合同 `bid {"contract": id, "price": p}`**：每周放出 `2` 或 `3` 个镜像对，共 `4` 或 `6` 份（抽到同城的那对作废，偶尔更少），都在该周第 1 天内放出，`28` 天固定流量，流量 `units` 为 `5..25`，保留价 `reserve = units * 单价基准 * 28 * 144 / 35 * 1.2`。截标期 `144` tick，`deadline` 当 tick 先判标，再处理动作。截标前可重复投标，以最后一次为准。要求两端均有已建 PoP、7 天 SLA `>= 0.90` 且 `0 < p <= reserve`，最低价中标；同价时 SLA 高者优先，再同则座位小者优先。合同款按天分期发放；若合同期内逐 tick 送达率的均值 `< 0.99`，结算时扣罚 `2 * 中标总价`（局末未到期合同按已执行比例折算）。合同流量 `units` 每 tick 叠加到该城市对的同类需求上，同样占用链路和端口，也同样按普通业务单价计收入；合同款另外发放。送达率按该城市对该类别的全部流量计算。
- **双边互联 `peer_offer` / `peer_accept`**：在双方均有已建 PoP 的城市 `c` 报出 `(units, price, ticks)`（报价有效期 `144` tick）；对方 `peer_accept` 后，接受方是买方，发起报价方是卖方。买方可借卖方网络（到达卖方有已建 PoP 而买方无 PoP 的城市 `j`）获取单端需求 `D_aj * 占比_k * (s_{a,k} / 2) * ((F_ra + F_rj) / 2)`，并每 tick 固定向卖方支付 `units * price`。买方流量先走到互联城市 `c`（沿用该段的显式路由或默认路由），再走卖方网络（优先走卖方有租约的链路，走不通时退回普通最短路），后一段计入卖方链路负载；超出 `units` 的流量按比例缩放。

### 2.7 随机事件（均镜像成对发生）
下列频率按一个镜像对计算。

- `live`（每天 `0..2` 次，直播突发，提前 `12..36` tick 预告，预告倍数带 `×U(0.5, 1.5)` 噪声）：某城特定类目视频需求增加 `(倍数 - 1)` 份（倍数 `U(3, 8)`，持续 `6..24` tick）。
- `fail` / `repair`（无预告链路故障。8 周内每条链路的期望次数：`land` `0.25`、`mw` `0.4`、`sub` `0.6`。海缆持续 `288..1008` tick，其余按均值 `48` 的指数分布持续 `6..1008` tick）与 `maint`（每天 `60%` 概率，计划维护，提前 `144` tick 公告，持续 `6..12` tick）：期间该链路容量归零。
- `power`（每座城市每周 `1%` 概率，城市断电，持续 `2..12` tick，无 UPS 的 PoP 瘫痪）、`ddos`（每天 `35%` 概率，持续 `3..18` tick，双方在各自已建 PoP 中按同一相对位置各挑一座，端口负载 `×5`，开 `scrub` 免疫；不进 `ev`，见观测字段 `ddos` 和 `res`）、`rain`（每天 `50%` 概率，提前 `12` tick 预报，大区微波容量减半 `12..48` tick）、`hike`（从第 2 周起每周 `60%` 概率，提前 `144` tick 公告，大区链路基础租价 `+20%..50%` 持续 `1` 周）。

## 3. 通信协议（`stdin / stdout` 逐行 JSON）

1. **握手 `init`**：
   ```json
   {"type": "init", "seat": 0, "ticks": 8064,
    "map": {"cities": [{"id": 0, "x": 0.0, "y": 0.0, "region": 0, "pop": 0.01, "elec": 1.0, "land": 1.1}],
            "links":  [{"id": 0, "u": 0, "v": 1, "type": "land", "cap": 200, "lat": 5.0, "base": 0.001}],
            "regions": [{"id": 0, "tz": -2}]},
    "start": {"you": [c1, c2], "opp": [c3, c4]},
    "rules": {...}}
   ```
   收到后回复 `{}`。
2. **每 tick 观测 `obs`**：
   - 常规字段：`t` (`0..8063`), `cash`, `bankrupt`, `spot`（滞后 1 tick 且含 `±10%` 噪声的各链路现货利用率）, `lp`（各链路未打折单价）, `avail`（各链路剩余可租容量）, `down`（当前断开链路 `id` 列表）, `ev`（本 tick 新增事件列表，字段见下表）, `res`（上一 tick 动作执行与错误回报，失败项最多列 `50` 条；租约回执里的 `lease` 是请求在 `lease` 列表中的下标，`id` 是租约 id）, `pops`（本方 `[city, ready_tick, port_cap, cache_cap, has_ups, scrubbing]` 列表）, `opp_pops`（对手含在建 PoP 城市列表）, `load`（本方各链路骨干负载）, `own_lease`（本方各链路已租容量）, `port`（本方各 PoP 端口负载）, `stat`（`video / rt / backup` 三类 `[需求, 有效送达, 收入]`）, `ddos`（正被攻击的本方 PoP 列表）, `queued`（备份延后队列 `{"a-b": units}`）, `missed`（累计超时/坏输出次数）, `time_pool`（剩余时间池秒数）。
   - 条件附带字段：租约变化时附 `leases`（`[[lease_id, link, units, end_tick], ...]`）；每 `6` tick（`t % 6 == 5`）附 `groups`（`[a, b, cls, 平均需求, 送达率, 平均延迟ms, 平均丢包率]`）；每日末（`t % 144 == 143`）附 `day`（`shares`: `{城市: [A 三类份额, B 三类份额]}`, `prices`: 双方的大区价格倍数, `heat`, `gp`: 当日毛利, `sla`: 近 7 天 SLA）。

   | 事件 `type` | 字段 |
   |---|---|
   | `live` | `city`, `cat`, `mult_est`（带噪预告倍数）, `start`, `end` |
   | `fail` | `link`, `start` |
   | `repair` | `link` |
   | `maint` | `link`, `start`, `end` |
   | `power` | `city` |
   | `rain` | `region`, `start`, `end` |
   | `hike` | `region`, `mult`, `start`, `end` |
   | `contract` | `id`, `a`, `b`, `cls`, `units`, `days`, `deadline`, `reserve` |
   | `award` | `contract`, `winner`（座位或 `null`）, `price` |
   | `peer_offer` | `id`, `city`, `units`, `price`, `ticks`, `expires`（只发给对方） |

3. **每 tick 动作 JSON**（全部字段可选，省略表示维持原状或不执行）：

## 4. 终局净资产与正式计分

- **终局净资产 `NW`**：
  `NW = 现金 + 固定资产账面总值（PoP / 扩容 / 缓存 / UPS 按 365 天即 52560 tick 直线折旧） + 剩余租约未摊销预付款 * 0.5 + max(0, 最后 7 天日均毛利) * 14`
  （日毛利 = 当日业务、合同与互联总收入 − PoP/缓存/清洗运营费 − 互联支出 − 租约当期摊销 − 合同罚金）。
- **正式评分版本：`scoring_v2`，满分 100。** 固定对阵 3 个参考对手，在本次抽到的每个种子上交换座位。每局得分：
  $$s = 50 + 50\tanh\left(\frac{NW_T-NW_R}{102079.91}\right).$$
- 对全部对手、种子与座位等权平均得到正式 `score`。净资产相同为 50 分，白板不固定为零分，参考对手也不固定为满分。每份提交默认运行 `3 * 64 * 2 = 384` 局；N 个场景共 `6N` 局。
- 映射尺度 `102079.91` 来自独立完整基线对局的正绝对分差中位数除以 `atanh(0.6)`，在评分前冻结；不根据参赛程序成绩调整。
- **世界盐值**：地图只由种子决定。随机事件、需求噪声和背景负载另用盐值派生：本地工具用 `practice`，正式评分用私有盐值，所以同一种子在本地和正式赛的事件序列不同。

- **每次随机、多局平均**：每次评测重新均匀抽取 N 个互不重复的场景种子，默认 N=64，可增加场景数。参考对手池、生成规则、完整局长及运行限制固定；同一批提交共享本次种子并交换座位/角色，对手、场景、座位分别等权。不会选择多次运行中的最好成绩，也不跨次缓存成绩。每个 seed 直接从操作系统安全随机源抽取（secrets/SystemRandom），去重并排除校准种子，不经固定主种子扩展；报告保存完整 seed 列表，供重放核查。
- **统计与版本**：成绩包含 `scoring_version = "scoring_v2"`、`score`（0–100）、`max_score = 100`、分项、原始指标、出错局数和 95% bootstrap 区间。区间按完整种子块重采样，保留同种子下座位、对手与赛制之间的相关性；只有一个种子时不报告区间。
- **可比性**：报告包含冻结配置、引擎、对手及提交源码指纹。旧版成绩和练习成绩不进入新版正式汇总；不同配置指纹的成绩不直接混用。这里的百分制表示本题固定评测下的表现，不是最优率或胜率。
- **本地自测**：`scripts/spar.py` 同样默认随机抽取场景，使用 `--seed-count N` 指定数量，使用 `--seeds 123 456` 重放。公式与正式赛一致，但对阵公开基线，始终标记 `official = false`。正式入口中显式指定 `--seeds` 的重放或缩短局长的运行也标为非正式。
